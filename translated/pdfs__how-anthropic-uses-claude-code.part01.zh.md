## 用于数据基础设施的 Claude Code

数据基础设施团队负责为公司各团队组织全部业务数据。他们用 Claude Code 自动化日常数据工程任务、排查复杂的基础设施问题，并为技术与非技术团队成员创建有文档记录的工作流，让他们能够独立访问和操作数据。

### Claude Code 主要用例

#### 借助截图调试 Kubernetes

当 Kubernetes 集群宕机、无法调度新的 Pod 时，该团队用 Claude Code 来诊断问题。他们把仪表盘截图喂给 Claude Code，它便逐个菜单地引导他们在 Google Cloud 界面中排查，直到找到一条提示 Pod IP 地址耗尽的告警。随后 Claude Code 给出了创建新 IP 池并将其加入集群的确切命令，从而无需再请网络专家介入。

#### 面向财务团队的纯文本工作流

该团队向财务团队成员演示了如何编写纯文本文件来描述其数据工作流，然后将其载入 Claude Code 以实现全自动执行。没有任何编程经验的员工可以描述诸如“查询这个仪表盘、获取信息、运行这些查询、产出 Excel 输出”之类的步骤，Claude Code 便会执行整个工作流，包括主动索要日期等必需输入。

#### 面向新员工的代码库导航

当新的数据科学家加入团队时，他们会被引导使用 Claude Code 来浏览其庞大的代码库。Claude Code 会阅读他们的 Claude.md 文件（文档），识别与特定任务相关的文件，解释数据管道的依赖关系，并帮助新成员理解哪些上游数据源为仪表盘提供数据。这取代了传统的数据目录与可发现性工具。

#### 会话结束时的文档更新

该团队会请 Claude Code 在每个任务结束时总结已完成的工作会话并提出改进建议。这就形成了一个持续改进的闭环：Claude Code 依据实际使用情况帮助打磨 Claude.md 文档与工作流说明，使后续迭代更有效。

#### 跨多个实例的并行任务管理

在处理长时间运行的数据任务时，他们会在不同仓库中为不同项目打开多个 Claude Code 实例。每个实例都保有自己的完整上下文，因此当他们几小时或几天后切回来时，Claude Code 仍清楚记得他们在做什么、停在哪里，从而实现不会丢失上下文的真正并行工作流管理。

### 团队成效

- **无需专门技能即可解决基础设施问题**：解决了那些通常需要拉来系统或网络团队成员才能处理的 Kubernetes 集群问题，靠 Claude Code 诊断问题并给出确切的修复方案。
- **加速上手**：新的数据分析师与团队成员无需大量指导，就能快速理解复杂系统并做出有意义的贡献。
- **强化支持工作流**：可以处理大得多的数据量，并识别出人类无法人工审核的异常（例如监控 200 个仪表盘）。
- **实现跨团队自助服务**：没有编程经验的财务团队如今可以独立执行复杂的数据工作流。

### 数据基础设施团队的首要建议

#### 编写详尽的 Claude.md 文件

你在 Claude.md 文件中把工作流、工具与期望记录得越好，Claude Code 的表现就越好。这使得 Claude Code 在已有既定模式的场景下（例如搭建新的数据管道）特别擅长处理常规任务。

#### 对敏感数据使用 MCP 服务器而非 CLI

他们建议用 MCP 服务器而不是 BigQuery CLI，以便对 Claude Code 能访问什么保持更好的安全控制，尤其是在处理需要留痕日志或存在潜在隐私顾虑的敏感数据时。

#### 分享团队使用会话

该团队举办过多次分享会，让成员互相演示自己的 Claude Code 工作流。这有助于传播最佳实践，也展示了他们自己原本可能发现不了的不同使用方式。

## 用于产品开发的 Claude Code

Claude Code 团队用他们自己的产品来构建 Claude Code 的更新，扩展该产品的企业级能力与智能体循环（agentic loop）功能。

### Claude Code 主要用例

#### 使用自动接受模式快速做原型

工程师通过启用“自动接受模式”（shift+tab）并搭建自主循环来用 Claude Code 快速做原型：Claude 编写代码、运行测试并持续迭代。他们把不熟悉的抽象问题交给 Claude，让它自主工作，然后审阅完成度 80% 的方案，再接手做最后的打磨。团队强调要从干净的 git 状态开始，并定期提交检查点，这样一旦 Claude 跑偏，就能轻松回退任何错误改动。

#### 核心功能采用同步编码

对于涉及应用业务逻辑的更关键功能，团队会与 Claude Code 同步协作，给出带有具体实现说明的详细提示词。他们会实时监控过程，以确保代码质量、符合风格指南以及架构得当，同时让 Claude 承担重复性的编码工作。

#### 构建 Vim 模式

他们最成功的异步项目之一是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个功能（尽管它并非优先事项），最终实现中约 70% 来自 Claude 的自主工作，只需几轮迭代即可完成。

#### 测试生成与缺陷修复

他们在实现功能之后用 Claude Code 编写全面的测试，并处理拉取请求（PR）评审中发现的简单缺陷。他们还利用 GitHub Actions 集成，让 Claude 自动处理 PR 评论中提出的问题，例如格式问题或函数重命名。

#### 代码库探索

在接触不熟悉的代码库（如 monorepo 或 API 侧）时，团队用 Claude Code 快速理解系统的运作方式。他们不再等待 Slack 回复，而是直接向 Claude 索要解释与代码引用，从而省下大量上下文切换的时间。

### 团队成效

- **更快的功能实现**：成功交付了 Vim 模式这样的复杂功能，其中 70% 的代码由 Claude 自主编写。
- **提升开发速度**：可以快速做原型并在想法上迭代，而不会陷在实现细节里。
- **通过自动化测试提升代码质量**：Claude 生成全面的测试并处理常规缺陷修复，在减少人工投入的同时保持高标准。
- **更好的代码库探索**：团队成员无需等待同事回复，就能快速理解 monorepo 中不熟悉的部分。

### Claude Code 团队的首要建议

#### 创建自给自足的循环

让 Claude 通过自动运行构建、测试与 lint 来验证自己的工作。这使 Claude 能更长时间自主工作，并发现自己的错误；当你让 Claude 在写代码之前先生成测试时，效果尤其明显。

#### 培养任务分类的直觉

学会区分适合异步处理的任务（外围功能、原型制作）与需要同步监督的任务（核心业务逻辑、关键修复）。产品边缘的抽象任务可以用“自动接受模式”处理，而核心功能则需要更密切的监督。

#### 撰写清晰、详细的提示词

当组件名称或功能相似时，你的请求必须极其具体。提示词越好越详细，你就越能放心让 Claude 独立工作，而不会意外改动代码库中不相干的部分。

## 用于安全工程的 Claude Code

安全工程团队专注于保障软件开发生命周期、供应链安全与开发环境的安全。他们大量使用 Claude Code 来编写和调试代码。

### Claude Code 主要用例

#### 复杂基础设施调试

在处理事故时，他们把堆栈跟踪与文档喂给 Claude Code，让它沿着代码库追踪控制流。这大幅缩短了生产问题的解决时间，使他们能用大约 5 分钟理解那些原本需要 10–15 分钟人工扫读代码才能搞清的问题。

#### Terraform 代码评审与分析

对于需要安全审批的基础设施变更，他们把 Terraform 计划复制到 Claude Code 中，问“这会产生什么影响？我会不会后悔？”这带来了更紧密的反馈闭环，也让安全团队更容易快速评审和批准基础设施变更，减少开发流程中的瓶颈。

#### 文档综合与运维手册

他们让 Claude Code 摄取多个文档来源，生成 markdown 运维手册、故障排查指南与概览。他们把压缩后的文档当作调试真实问题的上下文，这比检索整个知识库更高效。

#### 测试驱动开发工作流

他们不再沿用过去“设计文档 → 蹩脚代码 → 重构 → 放弃测试”的模式，而是让 Claude Code 给出伪代码，引导它走测试驱动开发，并在它卡住时定期介入引导，从而得到更可靠、更可测试的代码。

#### 上下文切换与项目上手

在为“dependant”（一个用于安全审批工作流的 Web 应用）这类既有项目做贡献时，他们用 Claude Code 编写、评审并执行以 markdown 形式存放在代码库中的规格说明，从而在几天内而不是几周内做出有意义的贡献。

### 团队成效

- **缩短事故解决时间**：原本需要 10–15 分钟人工扫读代码的基础设施调试，现在约 5 分钟即可完成。
- **改善安全评审周期**：用于安全审批的 Terraform 代码评审快得多，开发者不再因等待安全团队批准而被阻塞。
- **增强跨职能贡献**：团队成员能在几天内（而不是经历数周的上下文积累后）对项目做出有意义的贡献。
- **更好的文档工作流**：从多个来源综合出的故障排查指南与运维手册，带来了更高效的调试流程。

### 安全工程团队的首要建议

#### 大量使用自定义斜杠命令

在整个 monorepo 的所有自定义斜杠命令实现中，安全工程团队占了 50%。这些自定义命令简化了特定工作流，并加快重复任务的执行。

#### 让 Claude 先开口

他们不再索要代码片段式的定向回答，而是让 Claude Code“边做边提交你的工作”，让它在定期检查下自主工作，从而得到更全面的方案。

#### 善用它来写文档

除编码之外，Claude Code 非常擅长综合文档并生成结构化输出。他们提供写作样例与格式偏好，就能得到可直接用于 Slack、Google Docs 等工具的文档，避免在界面之间来回切换的疲劳。

## 用于推理的 Claude Code

推理团队负责管理记忆系统：在 Claude 读取你的提示词并生成回复的过程中，该系统用于存储信息。团队成员（尤其是那些刚接触机器学习的人）可以大量使用 Claude Code 来弥合这一知识差距、加速工作。

### Claude Code 主要用例

#### 代码库理解与上手

在加入复杂代码库时，团队高度依赖 Claude Code 来快速理解架构。他们不再手动检索 GitHub 仓库，而是让 Claude 找出哪些文件调用了特定功能，几秒钟就能得到结果，无需询问同事或手动查找。

#### 覆盖边界情况的单元测试生成

写完核心功能后，他们让 Claude 编写全面的单元测试。Claude 会自动补上被遗漏的边界情况，把原本要耗费大量脑力的工作缩短到几分钟，就像一个可供他们审阅的编码助手。

#### 机器学习概念讲解

团队成员没有机器学习背景，因此依赖 Claude 解释模型特有的函数与设置。原本需要花一小时 Google 搜索并阅读文档的事情，现在只需 10–20 分钟，研究时间减少了 80%。

#### 跨语言代码翻译

在不同编程语言中测试功能时，他们说明想测试什么，Claude 就用所需的语言（如 Rust）写出逻辑，从而无需仅为测试去学一门新语言。

#### 命令召回与 Kubernetes 管理

他们不再记忆复杂的 Kubernetes 命令，而是向 Claude 询问正确的语法，比如“如何获取所有 Pod 或 Deployment 的状态”，并得到基础设施工作所需的确切命令。

### 要点回顾

- 数据基础设施团队把仪表盘截图喂给 Claude Code，即可定位 Kubernetes Pod IP 耗尽问题并拿到修复命令；财务等无编程经验的成员也能用纯文本描述驱动整个数据工作流。
- 产品开发团队以“自动接受模式”（shift+tab）搭建自主循环做原型，先让 Claude 完成约 80%，再人工接手打磨；核心业务逻辑则改为同步协作。
- Vim 模式是异步项目的代表：约 70% 的最终实现来自 Claude 的自主工作，仅需少量迭代。
- 安全工程团队用 Claude Code 把事故定位从 10–15 分钟人工扫读压缩到约 5 分钟，并用它评审 Terraform 计划、生成运维手册、支撑测试驱动开发。
- 安全工程团队占整个 monorepo 自定义斜杠命令实现量的 50%，通过自定义命令固化重复流程。
- 推理团队用 Claude Code 补齐机器学习知识差距，把概念研究时间减少 80%，并自动生成覆盖边界情况的单元测试。
- 共同建议：写详尽的 Claude.md/文档、从干净的 git 状态出发、定期提交检查点、区分可异步与需同步监督的任务，并给出足够具体详细的提示词。
- 敏感数据访问优先走 MCP 服务器而非 CLI，以获得更好的安全与审计控制。
