## 用于推理的 Claude Code

### 团队成效

**加速机器学习概念学习**
研究时间减少 80% —— 过去需要花一小时用 Google 搜索的工作，现在只需 10–20 分钟。

**更快的代码库导航**
能在几秒内找到相关文件并理解系统架构，而不用去请教同事。

**全面的测试覆盖**
Claude 自动生成包含边界情况的单元测试，在保持代码质量的同时减轻心理负担。

**消除语言障碍**
可以在 Rust 等不熟悉的语言中实现功能，而无需专门去学习这门语言。

### 推理团队的实用技巧

**先测试知识库功能**
试着提出各种问题，看 Claude 能否比 Google 搜索更快地给出答案。如果它更快、更准确，那就是你工作流中一个能省时间的宝贵工具。

**从代码生成入手**
给 Claude 明确的指示，让它编写逻辑，然后验证正确性。这有助于在把它用于更复杂的任务之前，先建立起对其能力的信任。

**用它来写测试**
让 Claude 编写单元测试，能显著减轻日常开发工作的压力。利用这一能力保持代码质量，而不必花时间手工推敲所有测试用例。

## 用于数据科学与可视化的 Claude Code

数据科学与机器学习工程团队需要复杂的可视化工具来理解模型表现，但构建这类工具往往需要掌握不熟悉的语言与框架。Claude Code 让这些团队无需变成全栈开发者，也能构建生产级的数据分析仪表盘。

### Claude Code 的主要用例

**构建 JavaScript/TypeScript 仪表盘应用**
尽管团队「几乎不懂 JavaScript 和 TypeScript」，他们仍用 Claude Code 构建完整的 React 应用，用于可视化强化学习（RL）模型的表现与训练数据。他们放手让 Claude 从零编写完整应用，例如一个 5,000 行的 TypeScript 应用，自己无需理解这些代码。这一点很关键，因为可视化应用所需的上下文相对较少，也不需要理解整个单体仓库（monorepo），因此可以快速做出工具原型，用来理解模型在训练与评估期间的表现。

**处理重复性重构任务**
面对合并冲突，或是编辑器宏处理不了、又不足以构成大工程的半复杂文件重构时，他们会像用「老虎机」一样使用 Claude Code —— 先提交当前状态，让 Claude 自主工作 30 分钟，然后要么接受它的方案，要么重来一次。

**创建持久化的分析工具，而非一次性的笔记本**
团队不再构建用完即弃的 Jupyter 笔记本，而是让 Claude 构建可复用的永久性 React 仪表盘，供未来的模型评估反复使用。这很重要，因为理解 Claude 的表现「是团队最重要的事情之一」—— 他们需要了解模型在训练与评估期间的表现，而这「实际上并不简单，光盯着一个数字上涨，简单工具拿不到多少信号」。

**零依赖的任务委派**
对于完全陌生的代码库或语言中的任务，他们把整个实现委派给 Claude Code，借助它从单体仓库中收集上下文并执行任务的能力，自己不必参与实际编码过程。这让他们在自己的专长之外也能产出成果，而不必花时间去学习新技术。

### 团队成效

**实现了 2–4 倍的时间节省**
过去做起来枯燥但尚可手工处理的例行重构任务，现在完成得快得多。

**在不熟悉的语言中构建了复杂应用**
尽管 JavaScript/TypeScript 经验很少，仍做出了 5,000 行的 TypeScript 应用。

**从一次性工具转向持久化工具**
不再使用可丢弃的 Jupyter 笔记本，而是构建可复用的 React 仪表盘用于模型分析。

**直接的模型改进洞察**
亲身使用 Claude Code 的经验，为后续模型迭代中更好的记忆系统与用户体验改进提供了依据。

**支持可视化驱动的决策**
通过先进的数据可视化工具，更好地理解 Claude 在训练与评估期间的表现。

### 数据科学与机器学习工程团队的实用技巧

**把它当成老虎机**
在让 Claude 开始工作前先保存状态，让它跑 30 分钟，然后要么接受结果，要么重新开始，而不是纠缠于修正。重新开始往往比试图修复 Claude 的错误成功率更高。

**需要时打断它，追求更简单的方案**
在监督过程中，不要犹豫，停下 Claude 并问「你为什么要这么做？试试更简单的做法。」模型默认倾向于更复杂的解决方案，但对要求更简单方案的请求反应良好。

## 用于 API 的 Claude Code

API Knowledge 团队负责 PDF 支持、引用（citations）与网页搜索等功能，这些功能把额外的知识带入 Claude 的上下文窗口。在大型复杂代码库上工作，意味着不断遇到陌生的代码片段、花大量时间弄清某个任务该看哪些文件、并在改动之前先建立上下文。Claude Code 改善了这种体验：它像一个向导，帮助他们理解系统架构、定位相关文件、解释复杂的交互关系。

### Claude Code 的主要用例

**第一步的工作流规划**
任何任务，团队都把 Claude Code 当作「第一站」，让它指出修复缺陷、开发功能或做分析时该查看哪些文件。这取代了过去在开工前手动浏览代码库、收集上下文的耗时流程。

**跨代码库的独立调试**
团队如今有信心去处理代码库中不熟悉部分的缺陷，而不必向他人求助。他们可以问 Claude「你觉得你能修好这个缺陷吗？我看到的行为是这样」，而且往往立刻就有进展 —— 考虑到所需的时间投入，这在以前是不可行的。

**通过自用测试（dogfooding）进行模型迭代验证**
Claude Code 会自动使用最新的研究模型快照，因此成为他们体验模型变化的主要方式。这让他们在开发周期中直接获得关于模型行为变化的反馈，而这是他们在以往的发布中未曾体验过的。

**消除上下文切换的开销**
不必再把代码片段复制粘贴、把文件拖进 Claude.ai 并长篇解释问题，他们可以直接在 Claude Code 中提问，无需额外收集上下文，大幅减少了心智负担。

### 团队成效

**处理陌生领域时信心增强**
团队成员可以独立调试缺陷、排查不熟悉代码库中的事件。

**上下文收集显著省时**
免去了复制代码片段、把文件拖进 Claude.ai 的开销，减轻了心智上的上下文切换负担。

**轮岗上手更快**
轮换到新团队的工程师能快速浏览陌生代码库并做出有意义的贡献，无需大量咨询同事。

**开发者幸福感提升**
团队反馈日常工作中的摩擦减少，感觉更快乐、更有产出。

### API Knowledge 团队的实用技巧

**把它当作迭代伙伴，而不是一次性解决方案**
不要期待 Claude 立刻解决问题，而要把它当作与你共同迭代的协作者。这比试图一次就拿到完美方案效果更好。

**用它来在陌生领域建立信心**
不要犹豫，去处理你专长之外的缺陷或排查事件 —— Claude Code 让在本需要大量上下文积累的领域独立工作变得可行。

**以最少的信息开始**
只带上你真正需要的最少信息，让 Claude 引导你走完流程，而不是一上来就灌入大量解释。

## 用于增长营销的 Claude Code

增长营销团队专注于搭建效果营销渠道，覆盖付费搜索、付费社交、移动应用商店、电子邮件营销与 SEO。作为一个「一人非技术团队」，他们用 Claude Code 自动化重复性的营销任务，并构建以往需要大量工程资源才能实现的智能体工作流。

### Claude Code 的主要用例

**自动生成 Google Ads 创意**
团队构建了一个智能体工作流：处理包含数百条现有广告及其效果指标的 CSV 文件，找出表现不佳、需要迭代的广告，并生成符合严格字数限制（标题 30 个字符、描述 90 个字符）的新变体。系统使用两个专门的子智能体（一个负责标题，一个负责描述），可以在几分钟内生成数百条新广告，而无需跨多个广告活动手工创建。这让他们能够大规模测试与迭代，而以往要做到这一点需要投入大量时间。

**用于批量创意生产的 Figma 插件**
他们不再为付费社交广告手工复制、编辑静态图片，而是开发了一个 Figma 插件，用于识别画框，并通过替换标题与描述以程序化方式生成多达 100 个广告变体，把原本要花数小时的复制粘贴压缩到每批半秒。这带来了 10 倍的创意产出，让团队能在关键社交渠道上测试多得多的创意变体。

**用于广告活动分析的 Meta Ads MCP 服务器**
他们创建了一个与 Meta Ads API 集成的 MCP 服务器（模型上下文协议，MCP），用于直接在 Claude Desktop 应用中查询广告活动表现、花费数据与广告效果，免去了在多个平台之间切换做效果分析的需要，在每一分效率提升都意味着更好 ROI 的地方省下了关键时间。

**结合记忆系统的高级提示词工程**
他们实现了一个初级的记忆系统，记录各轮广告迭代中的假设与实验，使系统在生成新变体时能把此前的测试结果拉进上下文，形成一个自我改进的测试框架。这实现了手工根本无法追踪的系统性实验。

### 团队成效

**重复性任务大幅省时**
广告文案创作从 2 小时缩短到 15 分钟，腾出时间投入战略性工作。

**创意产出提升 10 倍**
借助自动生成与 Figma 集成，团队如今能在各渠道测试多得多的广告变体。

**像更大的团队一样运作**
团队能够承担以往需要专职工程资源才能完成的任务。

**战略重心转移**
团队可以把更多时间花在整体战略与构建智能体自动化上，而不是手工执行。

### 增长营销团队的实用技巧

**识别支持 API 的重复性任务**
寻找那些涉及重复操作、且所用工具提供 API 的工作流（例如广告平台、设计工具、分析平台）。这些是自动化最理想的候选，也是 Claude Code 价值最大的地方。

**把复杂工作流拆分为专门的子智能体**
不要试图用一个提示词或一个工作流处理所有事情，而要为具体任务创建独立的智能体（例如他们的标题智能体与描述智能体）。这样在处理复杂需求时更易调试，输出质量也更高。

**编码前充分头脑风暴并规划提示词**
先花大量时间用 Claude.ai 把整个工作流想透，再让 Claude.ai 生成一份完整的提示词与代码结构供 Claude Code 参考。同时要一步一步来做，而不是要求一次性给出解决方案，以免 Claude 被复杂任务压垮。

## 用于产品设计的 Claude Code

产品设计团队为 Claude Code、Claude.ai 与 Anthropic API 提供支持，专长于构建 AI 产品。即便不是开发者，也能用 Claude Code 弥合设计与工程之间传统的鸿沟，直接把自己的设计构想落地实现，而不必与工程师反复来回。

### Claude Code 的主要用例

**前端打磨与状态管理变更**
过去，为了字体、颜色、间距这类视觉微调，他们要写大量设计文档，并和工程师来回多轮反馈；现在他们直接用 Claude Code 实现这些改动。工程师注意到，他们在做「通常不会看到设计师去做的大规模状态管理变更」，从而实现了自己所设想的确切品质。

**GitHub Actions 自动建单**
借助 Claude Code 的 GitHub 集成，他们只需提交描述所需变更的 issue/工单，Claude 就会自动提出代码方案，甚至无需打开 Claude Code，为他们那批长期积压的打磨类任务形成顺畅的缺陷修复与功能完善工作流。

**快速交互式原型**
把设计稿图片粘贴进 Claude Code，就能生成功能完整的原型，工程师可以立刻理解并在此基础上迭代；这取代了过去「静态 Figma 设计稿 + 大量解释并转译为可运行代码」的传统循环。

**边界情况发现与系统架构理解**
他们用 Claude Code 梳理错误状态、逻辑流与不同的系统状态，从而在设计阶段就发现边界情况，而不是等到开发后期才暴露，从根本上提升了初始设计的质量。

**复杂的文案修改与法律合规**
对于在整个代码库中移除「research preview」这类表述的任务，他们用 Claude Code 找出所有出现位置、审阅周边文案、与法务实时协调变更并完成更新 —— 整个过程只用了两通 30 分钟的电话，而不是一周的来回协调。

### 要点回顾

- 推理团队用 Claude Code 把机器学习概念的研究时间缩短了 80%，并能用不熟悉的 Rust 语言实现功能。
- 数据科学与机器学习工程团队以「老虎机」式用法获得 2–4 倍的时间节省，用 5,000 行 TypeScript 应用替代一次性笔记本。
- API Knowledge 团队把 Claude Code 当作任何任务的「第一站」，显著减少了上下文收集与上下文切换的开销。
- 增长营销团队把广告文案创作从 2 小时压缩到 15 分钟，创意产出提升 10 倍，并以子智能体拆分复杂工作流。
- 产品设计团队让非开发者直接实现前端改动、自动建单与快速原型，把跨周协调压缩到两通电话。
- 跨团队的共同做法：先让 Claude 自主跑一段时间再验收结果，必要时打断它并要求更简单的方案。
