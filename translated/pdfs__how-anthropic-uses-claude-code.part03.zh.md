## 用于产品设计的 Claude Code

### 团队成效

**核心工作流被重塑**
Claude Code 成为主要的设计工具，Figma 与 Claude Code 有 80% 的时间处于打开状态。

**执行速度提升 2–3 倍**
过去需要与工程师大量来回沟通的视觉与状态管理改动，如今可以直接实现。

**周期从数周缩短到数小时**
像 GA 发布信息这类原本要花一周协调的复杂项目，现在通过两通 30 分钟的电话即可完成。

**两种截然不同的用户体验**
开发者获得「增强式工作流」（执行更快），而非技术用户获得「天哪，我居然成了开发者」式的工作流（过去完全不可能的新能力）。

**设计与工程协作改善**
由于设计师提前理解了系统约束与可能性，沟通更顺畅、问题解决更快。

### 产品设计团队的实用建议

**让工程师帮忙做好初始配置**
请工程同事协助完成代码仓库的初始设置与权限配置 —— 对非开发者来说，技术入门颇具挑战，但一旦配置完成，日常工作流就会发生质变。

**用自定义记忆文件引导 Claude 的行为**
写下明确指令告诉 Claude：你是几乎没有编码经验的设计师，需要详细解释、需要更小的增量改动。这会显著提升 Claude 回复的质量，也让整个过程不那么令人生畏。

**用图片粘贴做原型**
用 Command+V 把截图直接粘进 Claude Code —— 它非常擅长阅读设计稿并生成可用代码，是把静态设计稿变成工程立即可懂、可继续构建的交互式原型的利器。

## 用于强化学习工程的 Claude Code

强化学习工程团队专注于强化学习（RL）中的高效采样，以及集群内的权重传输。他们主要用 Claude Code 编写中小型功能、调试代码、理解复杂代码库，工作方式偏迭代，包含频繁的检查点（checkpoint）与回滚。

### Claude Code 的主要使用场景

**监督式自主的功能开发**
对中小型功能，团队让 Claude Code 编写大部分代码，同时保持监督，例如为权重传输组件实现鉴权机制。他们以交互方式工作：允许 Claude 主导，但在跑偏时把它拉回来。

**测试生成与代码评审**
在自己完成改动后，他们让 Claude Code 补充测试或评审代码。这套自动化测试流程在常规但重要的质量保障工作上节省了大量时间。

**调试与错误排查**
他们用 Claude Code 调试错误，效果参差不齐 —— 有时它能立刻定位问题并补上相关测试，有时却难以理解问题所在，但总体而言只要奏效就有价值。

**代码库理解与调用栈分析**
他们工作流中最大的变化之一，是用 Claude Code 快速获取相关组件与调用栈的摘要，取代了过去手工读代码或生成大量调试输出的做法。

**Kubernetes 运维指导**
他们经常向 Claude Code 询问原本需要大量 Google 搜索的 Kubernetes 运维问题，配置与部署方面的疑问都能立刻得到答案。

### 开发工作流的影响

**试错式方法成为可能**
他们现在采用「试试看、不行就回滚」的方法，频繁提交检查点，以便测试 Claude 的自主实现尝试、必要时回滚，从而更敢做实验。

**文档加速**
Claude Code 会自动补上有用的注释，在文档上省下大量时间；不过他们也指出，它有时会把注释加在奇怪的位置，或采用值得商榷的代码组织方式。

**提速但有局限**
Claude Code 能在他们「相对很少的投入」下实现中小型 PR，但他们也承认，它只有大约三分之一的概率能一次成功，否则就需要额外引导或人工介入。

### 强化学习工程团队的实用建议

**针对具体模式定制 Claude.md 文件**
在 Claude.md 文件中加入指令，避免 Claude 反复犯同样的工具调用错误，例如告诉它「用 pytest 而不是 run，不要不必要地 cd —— 直接用正确的路径」。这显著提升了稳定性。

**采用重检查点的工作流**
在 Claude 改动代码时定期提交，这样实验不成功时就能轻松回滚。这让你能在不担风险的前提下采用更具实验性的开发方式。

**先试一次成型，再转为协作**
给 Claude 一个简短提示，先让它尝试完整实现。如果成功（大约三分之一的概率），你就省下大量时间；如果不成功，再切换到更偏协作、更有引导的方式。

## 用于法务的 Claude Code

法务团队通过动手试验、以及了解 Anthropic 自家产品能力的意愿，发现了 Claude Code 的潜力。此外，有一位成员还有一个个人用例 —— 为家人制作无障碍工具，以及用于工作的原型，这些原型向非开发者展示了这项技术的力量。

### Claude Code 的主要使用场景

**为家人定制的无障碍方案**
团队成员为因医疗诊断而存在说话困难的家人构建了沟通助手。他们只用一小时就做出了一个预测输入应用：使用系统原生的语音转文字，给出候选回复，并用语音库朗读出来，填补了语言治疗师推荐的现有无障碍工具所留下的空白。

**法务部门工作流自动化**
他们构建了原型「电话树」系统，帮助团队成员找到 Anthropic 内部对口的律师，展示了法务部门如何在缺乏传统开发资源的情况下，为常见任务自建工具。

**团队协作工具**
管理者们构建了 G Suite 应用，自动完成每周团队进展汇总，并跟踪各产品的法务评审状态，让律师只需简单点击按钮就能标记需要评审的条目，而不必再靠电子表格来管理。

**快速原型验证方案**
他们用 Claude Code 快速构建可运行的原型，拿给领域专家看（例如把无障碍工具展示给 UCSF 的专家），在投入更多时间之前验证想法、并确认是否已有现成方案。

### 工作方式与影响

**在 Claude.ai 里规划，在 Claude Code 里构建**
他们采用两步流程：先在 Claude.ai 中头脑风暴与规划，再转到 Claude Code 进行实现，并要求它放慢速度、一步一步来，而不是一次性输出全部内容。

**可视化优先**
他们经常用截图告诉 Claude Code 希望界面长什么样，再基于视觉反馈迭代，而不是用文字描述功能。

**原型驱动的创新**
他们强调要克服「分享看起来很傻或像玩具的原型」的恐惧 —— 这类演示会启发他人看到原本想不到的可能性。

### 安全与合规意识

**对 MCP 集成的顾虑**
作为产品律师，他们会立刻识别出深度集成模型上下文协议（MCP）带来的安全影响，并指出随着 AI 工具接入越来越敏感的系统，保守的安全姿态会形成障碍。

**合规工具的优先级**
他们主张随着 AI 能力扩张，要尽快构建合规工具，并认识到需要在创新与风险管理之间取得平衡。

### 法务部门的实用建议

**先在 Claude.ai 中充分规划**
先用 Claude 的对话界面把整个想法捋清楚，再转到 Claude Code。然后让 Claude 把全部内容汇总成一份分步提示词用于实现。

**增量推进、以视觉为主**
要求 Claude Code 放慢速度、一次只实现一步，这样你可以从容复制粘贴而不会被淹没。大量使用截图来展示你想要的界面样子。

**不完美也要分享原型**
克服把「玩具」项目或未完成工作藏起来的冲动 —— 分享原型能帮助他人看到可能性，并在通常不互动的部门之间激发创新。

### 要点回顾

- 产品设计团队把 Claude Code 当作主要设计工具（Figma 与它 80% 时间同时打开），让设计师直接实现视觉与状态管理改动，执行速度提升 2–3 倍。
- 对非开发者而言，工程同事协助完成仓库与权限的初始配置是关键前提；自定义记忆文件（说明「你是设计师、需要详细解释与增量改动」）能显著提升输出质量。
- 强化学习工程团队用「试试看、不行就回滚」加上频繁提交检查点的方式，让 Claude 自主实现中小型功能并安全回滚，同时用 Claude Code 做测试生成、代码评审与调用栈理解。
- 该团队坦承局限：一次成功约占三分之一，因此建议先让 Claude 一次性尝试实现，失败再转为协作式引导；并在 Claude.md 中写明「用 pytest 而不是 run」之类规则以避免重复犯错。
- 法务团队用 Claude Code 在一小时内做出家用预测输入沟通助手，并自建「电话树」、周报自动化与法务评审跟踪等内部工具，证明非工程部门也能自建工具。
- 法务团队的工作方式是先在 Claude.ai 中规划、再在 Claude Code 中分步实现，并大量依赖截图而非文字描述；他们鼓励分享不完美的原型以激发跨部门创新。
- 作为产品律师，他们提示深度集成 MCP 的安全影响，主张随 AI 能力扩张尽快补齐合规工具，在创新与风险管理之间取得平衡。
