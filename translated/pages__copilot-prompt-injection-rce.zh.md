# GitHub Copilot：通过提示注入实现远程代码执行（CVE-2025-53773）

发布于 2025 年 8 月 12 日

#llm #agents #month of ai bugs

本文讲述一个既重要、又令人不寒而栗的提示注入（prompt injection）发现，它会导致 GitHub Copilot 与 VS Code 中开发者机器的完全沦陷。

其实现方式是修改项目的 `settings.json` 文件，把 Copilot 置于 YOLO 模式。

正如几天前在 Amp 中所述，智能体（agent）中一种可能被忽视的漏洞模式是：如果一个智能体能够写入文件，并能修改自身配置或更新与安全相关的设置，它就可能引发远程代码执行。这种情况并不罕见，是进行安全评审时始终应当排查的领域。

## 背景研究

在研究 VS Code 与 GitHub Copilot Agent 模式时，我注意到一个奇怪的行为……它可以在未经用户批准的情况下，在工作区中创建并写入文件。

这些编辑会立即持久化，它们并不像差异（diff）那样留在内存中等待审阅，而是被直接写入磁盘。

这是那种作为红队成员你一眼就知道可能不妙的细节之一……于是我开始研究，这能否被用来提权并执行代码。

### YOLO 模式

接下来，我研究了 VS Code 中依赖项目/工作区文件夹内设置的功能，并很快发现了一个有意思的点。

原来在 `.vscode/settings.json` 文件中，可以添加下面这一行：

` "chat.tools.autoApprove": true `

这会把 GitHub Copilot 置于 YOLO 模式。

它会禁用所有用户确认，于是我们可以运行 shell 命令、浏览网页，以及做更多事情！

有意思的是，这是一个实验性功能，但它默认就存在。我并没有下载特殊版本，也没有把自己的 VS Code 整体切换为实验模式。

此外，它在 Windows、macOS 以及 Linux 上都能生效。

## 把工作站接入僵尸网络——ZombAIs

当然，这意味着我们可以把开发者的机器作为 ZombAI 接入僵尸网络。

另外，出于好玩，我们还可以修改 `settings.json` 文件，把 VS Code 切换成 `Red` 配色方案之类的东西。

不过事情并未到此为止！这也意味着我们可以构建一个真正的 AI 病毒，它附着在文件上，并随着开发者下载和交互被感染的文件而传播。

最后但同样重要的是，为了证明我们完全控制了开发者的主机，我们展示了 Copilot 可以被劫持去下载恶意软件，并连上一台远程命令与控制服务器。

这意味着大门已经敞开，恶意软件、勒索软件、信息窃取程序等皆可进入。

真是可怕的东西。

## 构建 AI 病毒

看到这一幕，人们会注意到这基本上允许制造一种病毒。攻击者可以嵌入指令，一旦获得代码执行能力，额外的恶意软件就能感染其他 Git 项目（以及 RAG 来源），在其中嵌入恶意指令，并提交这些更改，甚至强制推送到上游。

随着其他开发者在毫不知情的情况下传播被感染的代码，这会引发进一步扩散。

最后，我们还需要谈谈不可见指令！

## 建议与修复

除了我分享的 YOLO 模式示例之外，实际上还有更多的攻击角度。当微软问我是否还有其他信息时，我又多看了一下，注意到还有其他有问题的地方，例如 AI 可以写入的 `.vscode/tasks.json`，或者添加伪造的恶意 MCP 服务器等等，这些都能导致代码执行。而且 AI 还能重新配置项目的用户界面与配置设置。

最近我注意到开发者经常使用多个智能体，因此也存在覆盖其他智能体配置文件的威胁（允许列表中的 bash 命令、添加 MCP 服务器……），因为这些文件通常也放在项目文件夹里。

理想情况下，AI 不应在未经人工事先批准的情况下修改文件。许多其他编辑器确实会显示差异（diff），从而可以由开发者批准。

## 负责任披露

在 2025 年 6 月 29 日报告该漏洞后，微软确认了复现结果并提出了几个后续问题。几周后，MSRC 指出这是他们已经在跟踪的问题，并将在 8 月修复。随着 8 月的补丁星期二（Patch Tuesday）发布，该问题现已修复。

向来自 Persistent Security 的 Markus Vervier 致意，他也识别并向微软报告了该漏洞。你可以在这里找到他们的分析文章。同时也要向 Ari Marzuk 致意，他看来也并行发现了该问题。

感谢 MSRC 与产品团队的成员在推动缓解该问题过程中提供的帮助。

## 结论

这是另一个示例，说明 AI 智能体可能不会乖乖待在自己的盒子里！通过修改自身环境，GitHub Copilot 可以提权并执行代码，从而危及开发者的机器。正如我所发现的，这是智能体系统中一种并不罕见的设计缺陷。

请持续留意这类设计缺陷，它们本应在威胁建模（threat modeling）过程中被轻松发现。
