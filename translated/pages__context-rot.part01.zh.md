# 上下文腐化：输入 Token 增加如何影响 LLM 表现

Kelly Hong

Anton Troynikov

Jeff Huber

大语言模型（LLM）通常被假定为对上下文进行统一处理——也就是说，模型处理第 10,000 个 Token 应与处理第 100 个 Token 一样可靠。然而在实践中，这一假设并不成立。我们观察到，即便在简单任务上，模型表现也会随输入长度变化而发生显著波动。

在本报告中，我们评估了 18 个 LLM，包括最先进的 GPT-4.1、Claude 4、Gemini 2.5 与 Qwen3 模型。我们的结果表明，模型并不会均匀地使用其上下文；相反，随着输入长度增长，其表现变得越来越不可靠。

Claude Sonnet 4、GPT-4.1、Qwen3-32B 与 Gemini 2.5 Flash 在重复词任务上的表现

LLM 近来的发展呈现出上下文窗口不断延长的趋势，最新模型的输入 Token 数已达数百万。由于这些模型在「大海捞针」（Needle in a Haystack，NIAH）[1] 等被广泛采用的基准上取得近乎完美的分数，人们往往假定它们在各处长上下文任务上的表现都是均匀的。

然而，NIAH 本质上是一个简单的检索任务：把一个已知句子（「针」）放入一篇由无关文本组成的长文档（「大海」）中，再提示模型将其检索出来。该基准虽具可扩展性，但通常考察的是直接的词面匹配，可能无法代表灵活的、以语义为导向的任务。

大海捞针（NIAH）设置示例

我们扩展了标准 NIAH 任务，以考察模型在此前较少探索的设置下的行为。我们研究具有语义匹配（而非直接词面匹配）的「针」所带来的影响，以及向「大海」内容引入变化所带来的影响。

此外，我们还纳入了一项使用 LongMemEval [2] 的对话式问答评估，以及一项合成任务——让模型复现一系列重复词。每项任务都被有意保持简单，并经刻意控制，以隔离单纯上下文长度所带来的影响。

我们证明，即便在这些最小化条件下，模型表现也会随输入长度增加而下降，且往往以出人意料、非均匀的方式发生。真实应用通常涉及远为更高的复杂度，这意味着输入长度的影响在实践中可能更为显著。

# 引言

现代 LLM 的输入上下文长度达到数百万 Token 已属常见。Gemini 1.5 Pro [3] 于 2024 年初率先引入其 100 万上下文窗口，随后是近期 GPT-4.1 的 100 万上下文窗口 [4] 与 Llama 4 的 1000 万 [5]。长上下文的用例极具吸引力：更长的上下文意味着 LLM 每次调用能处理更多信息，并生成更有依据的输出。

针对这些模型的长上下文评测常常显示其在各输入长度上表现一致。然而，这些评测范围狭窄，无法代表长上下文在实践中的使用方式。最常用的测试「大海捞针」（NIAH）是一个简单的词面检索任务，常被用来泛化模型可靠处理长上下文的能力。真实应用（如智能体任务或摘要）则要求在更宽泛、往往更含糊的信息上进行远为更多的处理与推理。

设计贴近现实的长上下文基准颇具挑战。任务往往随输入长度增加而变得更复杂，难以隔离表现下降究竟源于更长的输入还是本身更难的问题。为应对这一点，我们的实验在保持任务复杂度不变的前提下，仅改变输入长度——从而直接测量单纯输入长度带来的影响。

# 相关工作

评估模型长上下文能力最广泛使用的基准之一是「大海捞针」（NIAH）。它作为可扩展测试虽有用，但衡量的是一项狭窄的能力：词面检索。模型通常在 NIAH 上表现良好，这导致人们认为长上下文问题已基本解决。

然而，NIAH 低估了大多数长上下文任务在实践中所需的能力。NIAH 的变体，如 NoLiMa [6]（包含非词面匹配的针-问题对），揭示出显著的表现下降。其他看似难度相近的任务，例如 AbsenceBench [7]（考察模型识别给定文本片段是否缺失的能力），同样表现出随输入长度增长而出现的表现退化。

此外，长上下文任务往往把在干扰项之间消歧作为任务的一部分。一个例子是多轮共指消解（MRCR）[8] [9]，它涉及在多轮对话中、在相似的多个用户请求之间检索某个特定用户请求的第 i 次出现。然而，针对长上下文设置下干扰项影响的研究仍然缺乏。

长上下文任务中的一个重要因素是输入长度如何被放大。Latent List [8] 是一项要求模型在各种输入长度上执行固定数量 Python 列表操作的任务。研究测试了多种填充无关上下文的方式，揭示出对模型表现的非均匀影响 [1]。例如，添加在局部相互抵消的列表操作，相比添加 print 语句，会导致更显著的表现退化。这凸显了「无关内容」的类型如何重要，因为某些内容可能随输入长度增加而带来越来越高的复杂度。

类似地，Graphwalks [10] 是一项图遍历任务：模型被给定一个由十六进制哈希组成的有向图，然后被要求从随机节点出发执行广度优先搜索。增加输入长度意味着增大需要遍历的图规模，从而导致任务难度上升。很难把任务复杂度的增加与输入长度的增加区分开，这使得单纯隔离输入长度对表现的影响变得困难。这说明把输入长度作为关注变量加以隔离十分重要，而这对于理解 LLM 在长输入下实际如何表现至关重要。

# 大海捞针扩展

经典的大海捞针任务是把一个随机事实（「针」）放入一个长上下文窗口（「大海」）的中间，然后向模型询问该事实。

该任务的原始实现使用词面匹配的针-问题对。然而，实践中使用长上下文往往需要对含糊任务进行语义理解。

带词面匹配的大海捞针（NIAH）设置示例

NoLiMa 已证明，随着上下文长度增加，非词面匹配对模型构成挑战。该任务使用要求模型推断潜在关联的针-问题对，例如：

问题：哪个角色去过赫尔辛基？

针：其实，Yuki 住在 Kiasma 博物馆旁边。

NoLiMa - 针-问题对示例

为了回答这个问题，模型首先必须知道 Kiasma 博物馆位于赫尔辛基，然后建立这一潜在关联。这不仅考察模型的非词面匹配能力，也考察其世界知识。NoLiMa 中 72.4% 的针-问题对需要此类外部知识，使得该基准更接近于同时考察模型处理两项任务的能力，而非单纯的非词面匹配。

单独测试非词面匹配的影响仍属探索不足。此外，「词面」与「非词面」这种二元划分过于简化了现实场景中问答的复杂性。针-问题对存在于一个相似度谱系上，却都被归入这些宽泛的类别。

模型常常还需应对干扰项，已有研究表明这会降低表现 [11]。

在本报告中，我们区分干扰项与无关内容：

对比 - 干扰项 vs. 无关上下文

干扰项与「针」在主题上相关，但并不真正回答问题

无关内容与「针」和问题都无关

已有工作表明干扰项具有非均匀影响，但大多数评测涉及较短的输入长度和较旧的模型。当前最先进的模型被宣称对干扰项更具韧性，但其表现在各种输入长度上尚未得到广泛测试。

NIAH 另一个探索不足的方面是「大海」本身，它常被简单视为放大输入长度的手段，但这假定「大海」内容本身对任务表现没有影响。如果模型确实对「大海」的内容不敏感，那么改变这些内容（例如「大海」的主题或叙述流）就不应对结果产生影响。然而，这一假设在很大程度上仍未得到检验。

# 针-问题相似度

在现实应用中，模型常被期望处理含糊任务并在不依赖精确词面匹配的情况下识别相关信息。例如，当智能体被赋予一个需要在大型语料中搜索的任务时，用户很少为相关部分指定精确关键词。相反，模型必须推断相关性。

我们改变针-问题对的相似度，以其嵌入的余弦相似度量化。我们发现，随着针-问题相似度下降，模型表现随输入长度增加而退化得更显著。这反映了更贴近现实的情形——精确的问答匹配很少见，语义含糊加剧了长输入处理的挑战。

我们观察到一种清晰的模式：对于相似度较低的针-问题对，表现随输入长度退化得更快。

# 干扰项的影响

较早的模型已确立：干扰项会降低模型表现，且影响并不均匀。较新的模型被宣称能可靠处理任何干扰项，但随着输入长度增加，这一点是否仍然成立？

我们的实验揭示，随着输入长度增加，干扰项的影响及其非均匀性在各类模型（包括最新的最先进模型）上都会放大。我们还观察到各模型家族在处理含糊性时表现出不同的行为。

## 实验

从每个「大海」主题（PG 随笔与 arXiv 论文）中，我们取一个高针-问题相似度的「针」（八个中第二高），并人工撰写 4 个干扰项：

问题：「我从大学同学那里得到的最好的写作建议是什么？」

针：「我认为我从大学同学那里得到的最好的写作提示是每周都写作。」

干扰项：

「我从大学教授那里得到的最好的写作提示是每天都写作。」

「我从大学同学那里得到的最糟糕的写作建议是用五种不同风格写每篇文章。」

「我从同学那里得到的最好的写作建议是用三种不同风格写每篇文章，那还是在高中的时候。」

「我曾以为我从大学同学那里得到的最好的写作建议是用四种不同风格写每篇文章，但现在不这么认为了。」

## 结果

即便单个干扰项也会相对基线（仅「针」）降低表现，而加入四个干扰项会在此基础上进一步加剧退化。

我们还能看到干扰项的影响并不均匀。例如，在我们的 arXiv 大海与 PG 随笔针组合中，可以看到干扰项 3（红色）相对其他干扰项造成更明显的表现下降。

干扰项的影响：按单个干扰项划分的表现 - arXiv 大海/PG 随笔针

为进一步研究这种非均匀影响，我们分析各模型在四干扰项条件下的失败尝试。对于 arXiv 大海与 PG 随笔针组合，我们看到干扰项 2 与 3 在各模型的幻觉回答中出现得最频繁。

干扰项的影响：失败分析 - arXiv 大海/PG 随笔针

这些失败还揭示出模型在处理含糊性上的差异。Claude 模型始终表现出最低的幻觉率。具体而言，Claude Sonnet 4 与 Opus 4 尤为保守，倾向于在不确定时弃答，明确表示找不到答案。相比之下，GPT 模型的幻觉率最高，在存在干扰项时常常生成自信但错误的回答。

# 针-大海相似度

在长上下文任务中，无关上下文常被视为一个中性的占位符，用来放大输入长度。通常假定这些无关上下文的内容无关紧要，只要它不直接干扰任务即可。

然而，一个自然的问题是：针-大海相似度是否会影响任务难度？直觉上，如果「针」与「大海」的内容融为一体，模型提取「针」可能更加困难。

我们的发现揭示，针-大海相似度对模型表现有非均匀的影响。

## 实验

使用我们针-问题相似度实验中的「针」，我们设置实验来测试针-大海相似度的影响。

我们通过嵌入「大海」并为每个「针」检索前五个最相似的块，然后对其余弦相似度分数取平均，来衡量针-大海相似度。该过程在五个不同嵌入模型上重复以确保稳健。

在 PG 随笔「大海」中，PG 随笔针的平均针-大海相似度分数为 0.529，波动为 0.101，而 arXiv 针的平均针-大海相似度为 0.368，波动为 0.111。反之，在 arXiv「大海」中，arXiv 针的平均针-大海相似度为 0.654，波动为 0.0858，而 PG 随笔针相似度较低，为 0.394，波动为 0.105。

在每个「大海」上，我们测试语义相似的「针」与不相关的「针」。例如，我们在一个 Paul Graham 随笔「大海」中同时放入 PG 随笔针与 arXiv 针，以比较两种条件：

针-大海相似度：实验设置

## 结果

我们在两种「大海」类型（Paul Graham 随笔与 arXiv 论文）中测试 PG 随笔针与 arXiv 针。在 Paul Graham 随笔「大海」中，arXiv 针相对 PG 随笔针表现显著更好；换言之，当「针」在语义上不与「大海」融为一体时，模型表现更好。然而在 arXiv「大海」中，我们只观察到 arXiv 针与 PG 随笔针之间极小的表现差异。

针-大海相似度结果

仅在两主题上测试不足以得出「更高的针-大海相似度会降低该任务上模型表现」这一可推广的结论。然而，这确实凸显了长上下文处理的非均匀本质。即便任务结构与针-问题相似度保持不变，改变「针」与「大海」之间的语义相似度也能影响结果。这指向长上下文基准中一个探索不足的领域，以及未来研究的一个有意义方向。

# 大海结构

除针-大海相似度外，我们还考虑「大海」的结构模式。

如果「大海」由连贯的随笔组成，随机插入的「针」可能打乱思路的逻辑流动，使其更易被注意到。相反，在一个句子随机排序的打乱「大海」中，由于整体上下文缺乏结构，「针」可能更容易融入。这遵循一个假设：模型对上下文的逻辑流动敏感——以结构化、对顺序敏感的方式处理它。

出乎意料的是，我们发现结构性连贯始终损害模型表现。

尽管看似反直觉，但当「大海」保留思路的逻辑流动时，模型表现反而更差。打乱「大海」并去除局部连贯性，始终能改善表现。

## 实验

为评估「大海」结构的影响，我们创建两个变体：

原始：保留每段节选内思路的自然流动

打乱：句子在整个「大海」中被随机重排，以保持整体主题相同但无逻辑连续性

大海结构：实验设置示例

## 结果

在全部 18 个模型与各针-大海配置上，我们观察到一致的模式：模型在打乱的「大海」上比在逻辑结构化的「大海」上表现更好。

大海结构：18 个模型在原始与打乱「大海」上的平均表现

这些结果可能对模型的内部处理有所启示：输入的结构模式可能影响注意力机制的应用方式，尤其是在输入长度增加时。

虽然超出本报告范围，但这指向可解释性研究的一个潜在方向：输入结构如何影响注意力。理解这些随输入长度增加而出现的结构影响，可能有助于解释这些长上下文失败模式。

# LongMemEval

为在更贴近现实的设置下评估这些模型，我们使用 LongMemEval——一个用于对话式问答的长上下文基准。

对聊天助手使用长输入是维持后续对话相关历史的一种常见做法。为把「记忆」纳入聊天助手，一种朴素做法是把完整聊天历史放入后续对话的提示中。这要求模型执行两项任务（通常在单次调用中完成）：先找到对话历史的相关部分（检索），再以对来话查询有用的方式对其进行综合（推理）。

理想情况下，模型只被给予相关部分，从而可以专注于推理。加入无关上下文则增加一个识别何者相关的额外步骤，迫使模型同时执行两项任务。

我们通过两种条件，系统地测试在输入长度增加时加入这一额外步骤的影响：

聚焦输入：只包含相关部分，因此模型只需做简单的推理。

完整输入：使用完整的 113k Token LongMemEval 输入，其中包含无关上下文。此时，模型除推理外还必须在长上下文上执行检索。

我们核实模型在聚焦输入上表现出色，然后观察到在完整输入上表现持续退化。这种表现下降表明，加入无关上下文——从而增加一个额外的检索步骤——显著影响模型维持可靠表现的能力。

## 实验

给定用户与助手之间的聊天历史，模型的任务是回答一个与该聊天历史某部分相关的问题。

LongMemEval - 按问题类型划分的示例 [[2](#longmemeval-source)]

我们使用 LongMemEval_s，并筛选属于知识更新、时序推理与多会话类别的任务。随后我们人工清洗该数据集，因为有些问题过于含糊和/或无法回答，过滤掉 38 条提示，最终得到 306 条提示。这些提示平均约为 113k Token。

## 要点回顾

- 模型并不均匀地使用上下文：即便任务简单，表现也会随输入长度增长而显著且非均匀地退化。
- 该报告评估了 18 个 LLM（含 GPT-4.1、Claude 4、Gemini 2.5、Qwen3），并设计了针-问题相似度、干扰项影响、针-大海相似度、大海结构四项受控实验。
- 针-问题相似度越低，表现随输入长度退化得越快；该现象无法用配对本身的内在难度解释。
- 干扰项的影响不均匀，且随输入长度放大；Claude 模型幻觉率最低、倾向弃答，GPT 模型幻觉率最高。
- 针-大海相似度对表现的影响并不统一；结构连贯的「大海」反而持续拉低表现，打乱顺序能稳定改善表现。
- 在更贴近现实的对话式基准 LongMemEval 上，完整输入（含无关上下文）相较聚焦输入出现一致的性能退化，说明「检索 + 推理」同时进行会加重负担。
